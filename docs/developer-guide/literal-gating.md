# CRS mandatory-literal gating

The native Rust engine and the experimental engine kernel can prove, for a
subset of CRS regex rules, that **every** value matching the pattern contains at
least one literal from a required set. The engine scans the transformed
candidate value with an Aho-Corasick automaton; if none of the required literals
is present, the rule cannot match and its regex is skipped.

Soundness is one-sided: a literal that is not mandatory is never emitted, and a
rule is left `ungated` whenever extraction is uncertain. A miss therefore
proves the rule cannot match; a hit only means "run the regex".

## Artifact

`rules/crs/prefilter.json` is generated by `crs-prefilter-extract`:

```sh
nix develop -c cargo run --release --features crs-prefilter \
  --bin crs-prefilter-extract
```

The command also writes the human summary (`rules/crs/PREFILTER_SUMMARY.md`) and
the guest copy embedded by the Go reactor
(`wasm/coraza_reactor/rules/crs/prefilter.json`). Output is deterministic:
every list is sorted, groups are keyed by `(transform pipeline, case
sensitivity)`, and regeneration is byte-for-byte reproducible.

Schema **v2** changes:

- `rules[]` now contains a sound gate for every target class (body, headers,
  URI, cookies). The standalone body prefilter still filters on
  `body_relevant`; the Rust engine evaluates a gate per candidate value and can
  use header/URI gates too.
- `coverage` separates all-entry counts (`gated_entries`, `ungated_entries`)
  from the body-only counters used by the body-withholding fast path.
- Literal groups are per case sensitivity; a single any-of set may mix `(?i)`
  and case-sensitive members and each member is attributed to the
  representation that matches it.

## Extraction

The extractor parses a conservative PCRE subset and derives a disjunctive
literal set:

- **Finite expansion** is preferred: `foo\.bar`, `(?:wget|curl)`, `ab?c` and
  `x[Tt]rue` expand to the exact strings a match can take.
- **Bounded character classes** (`[aA]`, `[0-4]`, up to
  `MAX_CLASS_EXPANSION = 8`) expand into an alternation. Negated classes,
  ranges larger than the bound, POSIX classes and `\d`-style escapes stay
  opaque.
- **Adjacent literal runs** are combined: `~[\+\-]` yields `~+`/`~-`, and a
  suffix after a bounded class (`=[aA]`) keeps the longer run. This covers
  literal infixes and suffixes that are not a single atom.
- **Alternations** produce an any-of union; when the union is too large the
  extractor falls back to a literal common to every candidate. A branch whose
  only required literal is shorter than the minimum makes the whole
  alternation ungated.
- **Escaped and anchored forms** (`\xNN`, `\Q...\E`, `\b`, `^`, `$`) are
  handled; zero-width anchors do not break a literal run, consuming constructs
  do.
- **Consuming unknowns are opaque.** Conditionals and backreferences break
  adjacency instead of being treated as zero-width, so `ab(?(1)c|d)e` can never
  produce the unsound literal `abe`.
- **Minimum literal length is 2.** `..` (traversal), `/*` (comment) and `=`
  style suffixes are useful; a short literal can only cause a false hit (the
  regex runs), never a false negative.
- **`multiMatch` rules are never gated.** They evaluate every intermediate
  transform representation, so a gate over the final representation would be
  unsound. The extractor marks them ungated with an explicit reason. (The
  engine kernel consumes the same artifact, so this must hold for all
  consumers.)

`@pmFromFile`, `@pm`, `@contains`, `@streq`, `@beginsWith`, `@endsWith`,
`@within` and `@detectXSS` (`<` is a proven necessary condition) have their own
literal derivations. Negated operators, `@detectSQLi`, numeric comparison
operators and unreproducible transform chains stay ungated.

## Runtime

`GateSet` compiles one automaton per `(pipeline, case)` representation and
attributes every literal to the rule ids that require it. A hit mask is cached
per candidate value. Gate ids are dense and support up to 256 rules
(`GateMask` is four 64-bit words); rules beyond the cap stay ungated.

A gate is only attached when **every** literal group of the rule resolves to a
program pipeline. Dropping one group would lose a mandatory literal and could
skip a rule that still matches, so any unresolved group leaves the rule
ungated.

The Rust engine attaches gates for body-relevant rules only: scanning every
automaton over small header/URI values costs more than the regex it avoids.
The artifact still carries the all-target gates for consumers that scan those
representations.

| measure | before | after |
|---|---:|---:|
| gated entries (all targets) | 62 | 95 |
| ungated entries (all targets) | 296 | 263 |
| body-relevant gated | 62 | 76 |
| body-relevant ungated | 51 | 37 |
| distinct literals | 3145 | 3721 |

The generator output in `rules/crs/PREFILTER_SUMMARY.md` is authoritative.

## Benchmarks

`rust-engine-parity --bench` / `--profile`, 60 repetitions, release build,
bodyless/1/4/8 KiB synthetic form body:

| body | p50 before | p50 after | p99 after | regex evals run | skipped |
|---|---:|---:|---:|---:|---:|
| bodyless | 109.9 µs | 118.1 µs | 167.5 µs | 85 | 28 |
| 1 KiB | 281.0 µs | 265.7 µs | 318.8 µs | 145 | 137 |
| 4 KiB | 615.3 µs | 565.6 µs | 637.0 µs | 145 | 137 |
| 8 KiB | 1060.1 µs | 1007.5 µs | 1086.3 µs | 145 | 137 |

At 4 KiB the gate skips 137 regex evaluations versus 99 before (145 still run
versus 183). That is **48.6 % of all regex evaluations** skipped (137 of 282)
and **94.5 % of the evaluations that remain eligible** (`skipped / run`), up
from 54.7 %. The 4 KiB regex share falls from ~321 µs to ~283 µs; total p50
falls 8 %.

The 4 KiB p50 target of 480 µs is **not met**. The remaining cost is dominated
by the RCE command-list rules (`932125`, `932230`, `932235`, `932250`, `932260`,
`932370`, `932380`), which have no mandatory literal of two or more characters:
every command letter may be separated by a quote/bracket/`$IFS` filler, so the
only guaranteed literals are single bytes and the trailing delimiter class.
Gate those rules soundly needs an ordered-subsequence gate (letters in order,
fillers allowed), not a substring automaton. That is deliberately out of scope
for this change; their combined regex time is ~75 µs of the remaining ~283 µs.

## Soundness gates

- `cargo test --lib --features rust-engine,native-detect,engine-kernel,crs-prefilter`
  includes an adversarial test that another rule's literal hit cannot allow a
  gate, a test that a conditional cannot bridge a literal, and a test that a
  literal present in only one alternation branch is not emitted.
- `rust-engine-parity --engine both`: 2112/2112 corpus decisions agree with
  Coraza (unchanged), with no native-only false negatives.
- `engine-kernel-corpus`: 0 false negatives on its covered subset.
